# Heights of derivations

The closures that the ambient Mahlo rule builds name exactly the names derivable by the formers and an operator ([DS/Cedents](../DS/Cedents.agda), [DS/Naming/Cedents](../DS/Naming/Cedents.agda)), an ordinary inductive family over the names. The modules here measure those derivations by heights: closed trees whose labels are the small types, each node branching over its label, compared by the simulation order ([OrdinalGeometry/Height/Ordinals](../../OrdinalGeometry/Height/Ordinals.agda), [OrdinalGeometry/Height/Simulation](../../OrdinalGeometry/Height/Simulation.agda); see the [OrdinalGeometry README](../../OrdinalGeometry/README.md)). Premises are indexed by decodings of names, which are small types, so every derivation has a height of level ℓ, with one node per rule. These trees carry no connection to the ordinal geometry by themselves: the connection to presented ordinals is through the ranks of [OrdinalGeometry/Height/Presentation](../../OrdinalGeometry/Height/Presentation.agda), and the connection to the boundaries of reflections is through [OrdinalGeometry/Height/Reflection](../../OrdinalGeometry/Height/Reflection.agda). The first module, [Heights](../Heights.agda), sits directly in the Mahlo folder. Only [Comparison](Comparison.agda) uses induction–recursion, to compare with the two-sorted induction–recursive closure of [DS/Sorted/Realization/Discriminator](../DS/Sorted/Realization/Discriminator.agda).

## Derivations below a small height

| Module | Contents |
| --- | --- |
| [Heights](../Heights.agda) | Heights of derivations of the derivable names, one node per rule, branching over its premises (`height`), and of the stages of [DS/Naming/Trees](../DS/Naming/Trees.agda) (`stage-height`); the transformation from trees to derivations lands below a stage's height (`derived-height`). The fan of the heights of the codes of a closure of the requests is a small height (`closing`), strictly above a derivation of every name the closure names (`named-height`), and so, under extensionality, of every derivable name (`derivable-height`). Rule by rule, a derivation has a code naming its conclusion whose stage lies above it, since moving a stage into the joined family keeps its branching (`relabel-height`, `carry-height`, `raised`, `bounded`). So every derivation of every derivable name lies strictly below `closing` (`below-closing`, under extensionality for families of names), while no small height lies above Ord ℓ, the height of all small heights (OrdinalGeometry/Height/Ordinals' `not-small`). |
| [Least](Least.agda) | The closure height with no induction–recursion. `closing` is the fan of the stages' heights, and a stage may branch beyond what its derivation uses. Here each code of the closure is measured by the height of its own derivation (`derivation-height`), and the fan of those heights (`closure-height`) lies below every height strictly above all derivations, by construction (`closure-least`), and below `closing` (`least-below-closing`). A derivation taken from a moved tree keeps its height (`shift-derived`, `carry-derived`), so the code that `bounded` forms from a derivation has a derivation at least as high, rule by rule (`raised-derived`, `bounded-derived`), and every derivation lies strictly below the closure height (`below-least`, under extensionality). |
| [Comparison](Comparison.agda) | The two-sorted induction–recursive closure against derivations and against the closure from the ambient rule. A code's height, one node per constructor (`ir-height`), is the height of the code's derivation, both ways (`exact-below`, `exact-above`). Each derivation has a code naming its conclusion above it, under extensionality (`ir-members`, `ir-joint`, `ir-raised`, `ir-bounded`), so the fan of the codes' heights (`ir-closing`) lies strictly above every derivation (`ir-below-closing`) and is the least height that does (`ir-least`): it is the closure height of the derivable names. The fan from the ambient rule lies above it (`ir-below-mahlo`), and in both directions a code's derivation lies below a code of the other closure naming the same name (`coded-below`, `sorted-below`). Every presented ordinal lies below the closure height (`ir-presented-below`). Least's height is the closure height too, both ways (`ir-below-least`, `least-below-ir`), so measured by heights the induction–recursive closure closes where the ambient rule already does. |
| [Presentation](Presentation.agda) | Every presented ordinal lies below the closure height. A presentation P of level ℓ ([OrdinalGeometry/Presentation/CountableOrdinal](../../OrdinalGeometry/Presentation/CountableOrdinal.agda)'s `Countable-Ordinal𝒫`, with the ranks of OrdinalGeometry/Height/Presentation) is simulated by derivations. The name of a point x is the product over the natural-numbers code whose member at n is the name of the n-th enumerated point if that point lies below x, and the empty code otherwise; its derivation is built alongside, read along the decoding law of the natural code (`name`, `derivation`, `index-of`, `position`). The rank of each point lies below its derivation's height (`dominates`), and the rank of P below the height of the derivation over the whole enumeration (`dominates-whole`). So, under the ambient rule and extensionality, every presentation's rank lies strictly below the closure height of every operator (`presented-below`): the derivable names close beyond every presented ordinal of their level. |
| [Boundary](Boundary.agda) | Heights of derivations against the boundary Ω of a reflection R of the operator ([OrdinalGeometry/Height/Reflection](../../OrdinalGeometry/Height/Reflection.agda)), read as a height (OrdinalGeometry/Height/Ordinals' `decoded`), for a parent whose tree codes unfold and whose formers decode up to retraction. A derivation by the formers and the operator from seeds that R's child names lies below a child tree built rule by rule: the leaf at a constant former, a successor at an identity, and at a family rule the fork between the index premise's tree and the spread of the members' trees over the index's name (`forked`, `gathered`, `bounded`). So, under extensionality for families of names, it lies strictly below Ω (`below-boundary`), and no derivation reaches Ω (`excluded`). Conversely each child tree lies below a derivation from the child's names, the product over each label with the label's own name as a seed (`conclusion`, `derivation`, `dominates`), so Ω is the least height above every derivation from the child's names (`boundary-least`): the boundary is where generation from what the child names closes. The closure height from no seeds lies below the boundary of every reflection of the operator (`least-below-boundary`), and the carrier, whose family's tree code roots Ω, is not derivable from seeds the child names (`carrier-underivable`, by OrdinalGeometry/Height/Reflection's `carrier-unnamed`): [DS/Stationary/Derivable](../DS/Stationary/Derivable.agda)'s `not-derivable-from`, read in heights. |

## The Mahlo rule as regular heights

One layer of Φ's codes over a universe (U , T) names the ambient formers at U's families, and Φ's index and members at them, decoded as the formers and Φ themselves. Every operator Λ on families is a layer, and its stages are defined by recursion on the height, with no induction–recursion: the stage of a node is a child with a code of Λ over that child's stage,

    Stage Λ (node X f) = Σ x : X. pr₁ (Λ (Stage Λ (f x) , decoding Λ (f x))).

A node is regular for a layer's stages when it has a child and every code of its stage, with a family of codes indexed by that code's decoding, lies below one child, each strictly:

    a : Stage Λ t, b : decoding Λ t a → Stage Λ t
      ⊢ Σ z. f (pr₁ a) ⊏ f z × Π y. f (pr₁ (b y)) ⊏ f z.

Regularity is stated through the stages, so it depends on the layer.

| Module | Contents |
| --- | --- |
| [Stages](Stages.agda), [Stages/Map](Stages/Map.agda) | One layer of Φ's codes over a universe (`Code`, `decode`; as an operator on families, `codes`), and the stages of any layer along a height (`Stage`, `decoding`). A layer has Φ's codes when they are among its codes with their decodings (`Has-Codes`; `codes-have-codes`), and is functorial when its codes move along the maps of universes that keep decodings (`Functorial`). Along the simulation order the stages of a functorial layer include, their decodings kept: along s ⊑ t each code of s's stage is a code of t's (`include`, `included`), and along s ⊏ t each code over s's stage is one (`raise`, `raised`); a family code's moved family is the original one under extensionality for families of types (`family`). Stages/Map: along a map of universes that keeps decodings, each code goes to the same former at the images of its codes, with the same decoding under extensionality for families of types (`code-map`, `code-map-β`, `image-family`), so the layer of Φ's codes is functorial (`codes-are-functorial`). |
| [Regular](Regular.agda) | Regular nodes (`Regular`). At a regular node of a functorial layer with Φ's codes the stage is a closure of the ambient formers and Φ (`closure`): each former and Φ at a family of codes is a code of Φ at the bounding child, over the family raised into that child's stage (`over`, `head`, `tail`, `moved`, `coded`). So heights regular for the stages of Φ's codes give the rule (`mahlo`). Conversely, a closure L that names every code of a layer's stage at the fan of the heights of L's trees makes that fan regular (`trees-regular`, through `joined` and `gathered`). A closure of Φ names the stages of Φ's codes (`named`, `named-β`), so the rule gives heights regular for them (`regular`), and a closure of any operator names that operator's own stages (`staged`, `member`, `stage-name`), so the rule gives heights regular for the stages of every operator (`reflection-regular`). All under extensionality for families of types, with no induction–recursion. A node over a single child is not regular (`successor-irregular`). At a regular node the witnesses of a total relation upward closed along ⊏ are the decoding of no stage code (`witness-below`, `witnesses-are-not-decodings`), so regularity for relations is not had by collecting all witnesses into one code. |

## Univalent stages and unique names

These modules concern the passage from the plain ambient rule to its form with unique names, whose other conditional forms are in [DS](../DS/README.md). `Type-Hypotheses ℓ` is univalence with extensionality at ℓ ([DS/Univalent/Types](../DS/Univalent/Types.agda)), and completions are those of [DS/Univalent/Completion](../DS/Univalent/Completion.agda): a small type with an embedding into the codes and a covering map from the index commuting with them.

| Module | Contents |
| --- | --- |
| [Univalent](Univalent.agda) | Univalent stages. At a node the layer of codes of the formers and Φ over the children's univalent stages (`Layer`, `layer-decoding`) is completed, so each univalent stage is a small type whose decoding is an embedding (`univalent-stage`). A node is regular for relations (`Relationally-Regular`) when it has a child and every code of its stage, with a family of codes over its decoding, lies merely in one child's stage, the code's decoding and every member's named there. Given such a child, the family's index and members named there form a family of the child's codes decoding to the given one (`bounded-members`, `bounded-members-decode`, by extensionality for families of types), and the formers, the identity types and Φ's index and members at it are layer codes over the child (`product-layer`, `sum-layer`, `tree-layer`, `identity-layer`, `result-layer`, `branch-layer`); the stage names a code covered by layer codes (DS/Univalent/Completion's `names-in-the-completion`), so the child is needed only merely. So at a node regular for relations the univalent stage is a closure of Φ (`regular-closure`) with unique names (`regular-closure-has-unique-names`), and heights regular for relations give smallness with unique names, with no choice, excluded middle or resizing (`relational-passage`): `Type-Hypotheses ℓ → Completions ℓ (Set ℓ) → (Π Φ. Σ X f. Relationally-Regular Φ X f) → Univalent-Smallness ℓ`. Inside a univalent stage a family of members is a function by unique choice, so only the bound is asked for. Regularity for relations is a condition: the node over one leaf is not regular, since the leaf's stage completes an empty layer (`node-over-a-leaf-is-irregular`). Whether the Mahlo rule gives heights regular for relations, which would give the rule with unique names, is declared and not inhabited (`Relational-Regularity`). |
| [Fiberwise](Fiberwise.agda) | Stages completed child by child: the layer whose codes over a universe are the completion of Φ's codes over it (`completed-codes`), so each completed code keeps its child. The layer has Φ's codes (`completed-codes-have-codes`), and under `Type-Hypotheses` it is functorial, a completed code being merely the image of a code and so named in the target completion (`completed-codes-are-functorial`, through DS/Univalent/Completion/Map's `transfer`). So the Mahlo rule gives heights regular for these stages, and the stage of a regular node is a closure of the formers and Φ (Regular's `reflection-regular` and `closure`). A type is named at a child (`Named-At`) when it is equivalent to the decoding of a completed code over the child's stage; such names are unique (`named-at-is-proposition`) and move up the children (`moved-at`). A node bounds merely named families (`Named-Regular`) when, for a code and a family whose members are each merely named at some child, all are merely named at one child. At a regular node, with the global stage the completion of the node's codes, sums named in the global stage, the closure collecting names, `Named-Regular` and a choice of children for merely named families (`Children-Choice`) are equivalent (`global-collection`, `global-sums`, `named-regular-collection`, `collection-named-regular`, `named-regular-choice`, `choice-named-regular`); with its sums named the global stage is a closure of Φ with unique names (`global-closure`, `global-closure-has-unique-names`). So when the fans of the reflections of the completed codes of every operator bound merely named families, every operator has a closure with unique names (`unique-names-from-named-regular-fans`), and smallness gives its form with unique names (`named-regular-passage`). |
| [Fiberwise/Covers](Fiberwise/Covers.agda) | Weakly initial covers ([Foundation/Covers/WeaklyInitial](../../Foundation/Covers/WeaklyInitial.agda)) bound merely named families at the regular nodes of the fiberwise stages that name them. A node names the covers (`Names-Covers`) when the domain of each weakly initial cover of the decoding of each of its codes is the decoding of a code; at a regular node that names them every family whose members are each merely named at some child is merely named at one child (`covers-bound-named-families`, through `cover-bound` and `cover-bound-names`): `Global-Weakly-Initial-Covers ℓ → Regular → Names-Covers → Named-Regular`. The stage of a regular node of an operator joined with the covering one (DS/Univalent/Types' `type-covering`) names the covers (`covering-stages-name-covers`), so the fans of the closures of the completed codes of these operators bound merely named families (`covering-fans-are-named-regular`). They are the operators of DS/Univalent/Types' `type-names-passage`, where the same covers give closures that collect names. |
| [Hartogs](Hartogs.agda) | The Hartogs height of a closure: the fan of the heights of the code-valued well-founded relations on the closure's decodings (`Coded-Order`, `order-height`, `hartogs-height`), `hartogs-height = node (Σ c. Coded-Order (interpret c)) order-height`, whose index is a small type since the relations are valued in the closure's codes. It asks no classifier, unlike [OrdinalGeometry/Height/Hartogs](../../OrdinalGeometry/Height/Hartogs.agda), whose H(a) asks one of every code; a closure with unique names cannot have one under univalence. A height is regular for named families (`Regular-For-Named-Families`) when the join of the heights of any family of coded orders on merely named types, indexed by a decoding, lies strictly below it: the family is data, and only its naming is mere. Under `Type-Hypotheses`, with unique names the Hartogs height is regular for named families, with no excluded middle, choice or resizing (`unique-names-give-regularity`): unique choice names every member, each order pulls back to its member's code (`pulled-order`), the sum code names the members' total, and the order within the total's fibers, well-founded through the dependent lexicographic order (`fiber-order`, `no-steps`, `within-fiber`), lies above every member's (`fiber-below`, through `rank-at-along` and `whole-along`, ranks along order-keeping maps). In every closure every coded order on the natural numbers lies below the Hartogs height (`countable-below`), and the rule with unique names gives, for every operator, a closure whose Hartogs height is regular (`reflector-gives-regular-heights`). Whether the plain rule does is declared and not inhabited (`Regular-Hartogs-Heights`). Read classically, in a closure with power sets, regularity with `countable-below` makes the Hartogs height an uncountable regular cardinal, which ZF does not prove to exist (Gitik's model), so a model of the plain rule refuting `Regular-Hartogs-Heights` would refute the passage to unique names. |

## Not here

- Whether the fan of the stages' heights (`closing`) is itself least. It lies above the closure height (Least's `least-below-closing`), but its codes include trees whose stages branch beyond what their derivations use.
- Whether the closure height from no seeds lies strictly below a reflection's boundary: `least-below-boundary` gives `⊑`. Strictness would need one child tree above the derivations of all the closure's codes, a family indexed by a type the child need not name.
- A converse comparison with presented ordinals. Derivations here branch over arbitrary small types, so their heights are closed trees of OrdinalGeometry/Height/Ordinals, compared with presentations only through ranks, from below (`presented-below`).
- Whether the plain rule gives heights regular for relations (`Relational-Regularity`), fans bounding merely named families without covers, or closures with regular Hartogs heights (`Regular-Hartogs-Heights`).
